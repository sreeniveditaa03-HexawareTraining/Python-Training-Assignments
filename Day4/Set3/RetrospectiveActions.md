# Sprint Retrospective – Start, Stop, Continue

**Project:** E-Learning Platform  
**Sprint:** Sprint 01 – Learning Experience  
**Meeting:** Sprint Retrospective – Day 10  
**Facilitator:** Scrum Master  
**Participants:** Scrum Team  
**Actual Velocity:** 26 SP

## 1. Retrospective Objective

To inspect the team's collaboration, development process, and challenges during Sprint 01 and identify improvements for the next sprint.

## 2. Start – Stop – Continue

### START – Practices to Introduce

- Start validating API contracts and external dependencies before committing integration-dependent stories.
- Start assessing scope-change feasibility before adding new work to an active sprint.
- Start reviewing unfinished stories earlier to reduce end-of-sprint surprises.

### STOP – Practices to Avoid

- Stop accepting new sprint work without evaluating its impact on the Sprint Goal.
- Stop postponing dependency clarification until development is blocked.
- Stop treating partially completed stories as delivered functionality.

### CONTINUE – Practices to Maintain

- Continue using Daily Scrum to identify impediments.
- Continue prioritizing work that directly supports the Sprint Goal.
- Continue using automated tests and code reviews to maintain quality.
- Continue collaborative decision-making between the Product Owner and Developers.

## 3. SMART Retrospective Action Items

| Action ID | Improvement Action | Owner | Deadline | Success Measure |
|---|---|---|---|---|
| RETRO-01 | Validate API contracts for all integration-dependent stories before Sprint Planning | Dev 3 | Before next Sprint Planning | 100% of selected integration stories have reviewed contracts |
| RETRO-02 | Conduct a scope-impact review within one working day of every mid-sprint change request | Product Owner and Developers | Starting next sprint | Every request has a documented decision within one working day |
| RETRO-03 | Review all In Progress stories by the midpoint of the sprint and identify risks to completion | Scrum Master and Developers | By Day 5 of next sprint | All active stories reviewed and blockers recorded |

## 4. SMART Criteria

**Specific:** Each action addresses an identified improvement area.

**Measurable:** Each action has a defined success measure.

**Achievable:** Actions can be performed within the team's normal Scrum activities.

**Relevant:** Actions address API dependencies, scope changes, and incomplete work.

**Time-Bound:** Each action has a clear deadline.

## 5. Action Tracking

| Action ID | Priority | Status | Follow-Up |
|---|---|---|---|
| RETRO-01 | High | To Do | Next backlog refinement |
| RETRO-02 | High | To Do | Next Sprint Planning |
| RETRO-03 | Medium | To Do | Next sprint midpoint |

## 6. Retrospective Outcome

The team identifies dependency readiness and mid-sprint scope assessment as its main improvement areas.

The original Sprint Goal was achieved, but 4 SP remained incomplete, resulting in an actual velocity of 26 SP.

The Scrum Team agrees to apply the three SMART actions during the next sprint and inspect their effectiveness at the next retrospective.
